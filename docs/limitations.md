# Argus Project Limitations

This document tracks identified architectural, technical, data, and modeling limitations of the Argus multi-agent financial intelligence system. It is a catalogue of what the system's output *cannot* be trusted to do, and why. For how the system works and why it is built this way, see [`system-guide.md`](system-guide.md).

## 1. Data Availability & Freshness
- **Stale Price-Derived Fundamental Metrics**: The 7-day TTL cache for `FundamentalSignal` caches both static accounting metrics (like revenue growth) and price-derived multiples (like P/E ratio, market cap, and FCF yield). In fast-moving markets, the price-derived multiples used by the LLM agent will diverge from real-time market data.
- **ROA Used as ROIC Proxy**: The data fetcher maps Yahoo Finance's `returnOnAssets` directly to the `roic` field (`"roic": info.get("returnOnAssets")`). Return on Invested Capital (ROIC) and Return on Assets (ROA) are mathematically distinct financial ratios, potentially distorting capital efficiency evaluations.
- **Macro Reporting Lags**: The `MacroStatisticalAgent` relies on FRED data (e.g., CPI, UNRATE, Federal Funds Rate). These indicators suffer from significant reporting lags — weeks to months — and `data/macro_features.py` deliberately shifts each series forward by its real publication lag (FEDFUNDS 32d, UNRATE 35d, CPI 45d) so no training or inference row reflects information that was not yet public on that row's own date. This is correct point-in-time hygiene, but it means the regime classifier is *structurally* slow. Windowed inference compounds it on purpose: the classifier scores a trailing 36 month-end observations (`MACRO.inference_window_months`) rather than a single point, so the transition matrix rather than one noisy print drives the call — a genuine economic pivot therefore takes longer to register than single-point decoding would show.
- **No Point-in-Time Fundamentals**: `FundamentalAgent` derives a backtest session's `as_of_date` correctly from `session_seed`, but `market_data.fundamentals(ticker)` — a thin wrapper over `yfinance` — always returns the issuer's current-day ratios. yfinance exposes no historical fundamentals endpoint, so a `FundamentalSignal` stamped with a past `as_of_date` is still scored against today's P/E, margins, and leverage, not the ratios that existed on that date.
- **Backtesting Historical News Restrictions**: The NewsAPI free tier limits historical news queries to the trailing 28 days. Any backtest simulations set further in the past will fetch empty lists, rendering news/sentiment-based signals inactive.
- **NewsAPI Request Budget Is the System's Real Throughput Ceiling**: The free tier allows 100 requests/day, and a 20-ticker sweep spends 20 of them — a hard ceiling of roughly **5 full runs per day**, tighter than any Groq quota. `fetchers._NewsApiBudget` checks this before each request and persists the counter to `ARGUS_DATA_DIR`, so an exhausted budget degrades sentiment silently to `news_data_available: False` rather than erroring. The free tier also delays article availability by roughly 24 hours, so news-derived sentiment is **never same-day by construction**.
- **yfinance Is an Unofficial Client**: All price, fundamental, sector, and calendar data comes from private JSON endpoints behind the public Yahoo Finance website, not a documented API. There is no rate-limit contract, no `Retry-After` guarantee, no SLA, and no version stability. Response *shapes* have changed across minor versions (the code parses both DataFrame and dict forms of `.calendar`, and flattens MultiIndex columns defensively), and a future change could break ingestion without warning.
- **No Market Holiday Awareness**: Neither `MFTDataPipeline._is_market_hours()` (which only knows weekday vs. weekend and the 09:30–16:00 ET window) nor the GitHub Actions cron schedule knows about market holidays. A holiday tick finds no fresh candles and skips the graph invocation rather than running on stale data — degradation by design, but it means scheduled coverage is silently thinner than the cron implies.

## 2. LLM Dependencies & Constraints
- **API Rate Limits and Cost**: All three LLM-backed agents (fundamental, sentiment, portfolio synthesis) run on Groq. Running a large ticker universe quickly consumes tokens-per-minute quota, necessitating the `RateLimitGovernor`'s throttling, exponential backoff, and graceful degradation (skipping tickers, or propagating a 429 for the portfolio agent, which has no per-ticker fallback).
- **The Rate Governor Is Per-Process, Not Per-Account**: `RateLimitGovernor` is an in-process singleton that only observes calls its own process makes. `--workers 1` plus a `flock` on the data directory prevents a second API process, but the scheduled GitHub Actions collector is a genuinely independent process making calls against the *same* Groq key with its own ignorant governor. Neither can see the other's usage, so combined consumption can exceed what either believes it is spending. This gap is documented, not solved.
- **Groq Publishes No Requests-Per-Minute Header**: The governor can learn real tokens-per-minute and requests-per-day limits from response headers, but RPM is *always* enforced from the conservative bootstrap floor (`ARGUS_GROQ_RPM`, default 30) because no header reports it. A higher-tier account is therefore throttled below its actual entitlement unless the floor is raised manually.
- **Non-Determinism in Signal Generation**: While rigid JSON schemas and Domain-Knowledge Chain-of-Thought (DK-CoT) prompts are enforced, `FundamentalAgent`, `SentimentAgent`, and `PortfolioManagerAgent` are all powered by generative models. Conviction scores, decay-risk labels, and advisor notes can vary between identical inputs even at the near-zero temperatures configured.
- **Completion Budgets Are Model-Specific and Measured, Not Derived**: `max_tokens` for each agent (450 fundamental, 550 sentiment, 1000 portfolio) was measured empirically against specific gpt-oss models at `reasoning_effort="low"`, where reasoning tokens bill against the same budget as the answer. Changing model or reasoning effort without re-measuring will truncate responses mid-JSON, and every parse attempt will then fail.
- **Context Window Limits in Allocation**: The `PortfolioManagerAgent` receives the entire signal table for the universe. The `/analyze` schema caps requests at 20 tickers, which keeps this comfortably inside the configured models' context; a much larger universe reached through another entry point would degrade reasoning quality before it overflowed context.

## 3. Backtesting & Evaluation Limitations
- **No multi-year backtest**: There is no walk-forward engine or `/backtest` API endpoint. Yahoo Finance's 5-minute intraday data is only available for the trailing ~60 days, and the technical-indicator snapshot ARGUS's live pipeline computes cannot be reconstructed for older dates. `scripts/replay_backtest.py` replays recorded fixture sessions through the real graph instead, over whatever window has genuinely been captured.
- **Exactly One Captured Session Exists**: `tests/fixtures/` holds a single recorded session. The replay mechanism is proven correct and reusable, but the pre-registered evaluation running on top of it is severely underpowered — at single-digit `n` the bootstrap confidence intervals on rank IC and hit-rate routinely span zero. **A CI spanning zero at this sample size is a diagnostic about the measurement, not evidence about the system.** Accumulating enough resolved outcomes for sample size to stop being the binding constraint is the purpose of the unattended collector.
- **No Daily Equity Curve, So No Sharpe or Drawdown Reporting**: `backtesting/metrics.py`'s return-series block (Sharpe, Sortino, max drawdown, alpha/beta, VaR/CVaR) has no caller — nothing in the repo produces the daily equity curve it requires. The evaluation deliberately reports only the trade-level subset rather than these keys under a false premise, which means the system currently has **no risk-adjusted performance measure at all**.
- **Closed-Loop Replay Is Not Deterministic**: Because reliability weighting reads live ChromaDB state that reconciliation mutates between runs, only the open-loop path is checked for determinism (`check_replay_determinism`). Reproducing a closed-loop result requires reproducing the outcome store's state at that moment.
- **Parametric Memory Contamination**: While the system uses deterministic ticker anonymization to combat look-ahead bias, LLMs might still implicitly recognize high-profile companies (e.g., AAPL, NVDA) from unique combinations of their exact market cap, margins, and sector, leading to implicit bias.
- **Shortened Hash Collision Risk**: The deterministic anonymization logic in `fundamental.py` slices the MD5 hash hex digest to 4 characters (`[:4]`). A 4-character hex slice has only $16^4 = 65,536$ unique identifiers, raising collision risks in larger stock databases.

## 4. Financial Modeling & Execution Simulation
- **No Slippage or Market Impact Modeling**: The system calculates theoretical allocations based on end-of-day or intraday prices but does not account for execution slippage, bid-ask spreads, liquidity constraints, or the market impact of trading large sizes.
- **Static Covariance in Crisis**: The `RiskStatisticalEngine` utilizes historical covariance matrices for the SLSQP optimizer. Historical covariance notoriously breaks down during sudden market shocks or black swan events (when asset correlations tend to converge to 1), potentially under-calculating true Value-at-Risk (VaR).
- **Long-Only Constraint**: Currently, the system is designed to either allocate capital to long equity positions or hold cash reserves. It does not support short selling, options, or derivatives hedging. A bearish `macro_regime` can only reduce exposure, never profit from it.
- **Stop Losses Use Close-to-Close, Not True Range**: `close_to_close_stop_losses` computes its 14-period average from `series.diff().abs()` on daily closes rather than the Wilder true range (max of high−low, |high−prev close|, |low−prev close|) — it is not ATR despite borrowing ATR's period/multiplier convention. This **understates volatility for names with large intraday gaps**, placing stops closer than intended for exactly the securities that most need room.
- **Portfolio Beta Can Be Unmeasurable**: Missing benchmark data, zero benchmark variance, or insufficient constituent overlap yields `portfolio_beta=null` with a degraded note; the beta gate is skipped. Missing VIX and yield-curve readings remain null, and a failed direct VIX lookup blocks risk approval because the blackout check cannot run.
- **Failed Sector Lookups Pool Into One Bucket**: `get_sector` returns `"Unknown"` when the yfinance lookup fails, and the 40% sector concentration cap is applied per distinct sector string. Several unrelated tickers whose lookups all failed are therefore treated as a single concentrated sector, which can trigger a spurious `REDUCE` — or, if genuinely distinct sectors are misread as one, mask real concentration.
- **Half-Kelly Magnitudes Are Assumed, Not Fitted**: Position sizing anchors on assumed 8% average win and 4% average loss magnitudes (`PortfolioParams.kelly_avg_win_pct` / `kelly_avg_loss_pct`). Neither is fitted to ARGUS's own realized trade distribution, so the Kelly fraction is only as meaningful as those two guesses.
- **The Paper Equity Curve Is Synthetic**: ARGUS holds no positions and executes nothing, so the drawdown the kill switch gates on comes from `risk/paper_book.py` — matured decision outcomes weighted by `allocation_pct`, averaged per run and compounded. Runs are compounded at most once per horizon window to avoid double-counting overlapping returns, and partially-matured runs are averaged over the matured subset only. It is a reasonable proxy, but it is not a mark-to-market P&L, and the kill switch's authority rests entirely on it.

## 5. Modeling Assumptions & Parameter Provenance
- **Almost Every Threshold Is a Guess**: `argus/params.py` tags each constant with its provenance, and the honest summary is that most are `ARBITRARY` — indicator weights, conviction bases and ceilings, agent voting weights, VaR/CVaR/correlation limits, drawdown tiers, and the reconciliation horizon all have "no external basis". **There is currently no `CALIBRATED` value in the system.** The provenance tags are a to-do list marking every number that would need real evidence before a result depending on it should be believed.
- **Credit Assignment Is a Heuristic, Not Ground Truth**: `credit_primary_driver` attributes each realized outcome to a single agent via leave-one-out ablation, ranked by direction-flip first and baseline vote magnitude second. This deliberately avoids exact Shapley over the 2³−1 coalitions, but it is an approximation — and every downstream consumer (per-agent win rates, aggregator reliability weighting, Half-Kelly anchors) inherits its error.
- **Agent Reliability Is Sparse and Shrunk**: `get_agent_accuracy` shrinks win rates toward a 0.5 prior with k=10 pseudo-observations, so early measurements are heavily damped and a returned rate of 0.5 is ambiguous between "no data" and "measured 50%" — callers must inspect the sample count `n` to distinguish them. Rates are additionally scoped per macro regime, further thinning the sample available for any single weighting decision.
- **CONTRACTION May Go Unlabelled**: The HMM's contraction state is identified by NBER (`USREC`) recession enrichment clearing 2× the sample base rate. If no candidate state clears that bar, **no state is labelled CONTRACTION at all** and the regime can never be reported. This is deliberate — it replaced a heuristic that always assigned the label to some state, which is how the ZIRP era once got tagged CONTRACTION — but it means the aggregator's contraction override may simply never fire on a given trained artifact.

## 6. Architectural Trade-offs
- **Synchronous Database Bottlenecks**: The LangGraph state machine execution uses `SqliteSaver` checkpointers which operate synchronously. This prevents the use of true `async` graph invocations (`ainvoke`), causing the orchestration layer to block threads heavily during execution.
- **In-Process Singletons Constrain Deployment**: Both the rate governor and the kill switch are per-process singletons, so ARGUS **must** run with a single worker. `_assert_single_worker()` catches the argv/env spellings of a worker count, and an exclusive `flock` on `${ARGUS_DATA_DIR}/argus.lock` catches everything else — including two containers sharing one volume. This caps the API's throughput at one graph run at a time (enforced by a semaphore shared with the collector loop) and rules out horizontal scaling without redesigning both components.
- **The Kill Switch's Drawdown Gate Is Process-Global**: The threshold is fixed at startup from `ARGUS_RISK_TOLERANCE` and is not per-request. An `/analyze` call specifying a different `risk_tolerance` is still governed by the configured threshold; the mismatch is logged, not rejected.
- **A Macro Artifact Version Mismatch Degrades Silently**: `RegimeClassifier.load` refuses an artifact whose `hmmlearn`, `scikit-learn`, or feature-column list disagrees with the installed versions at major.minor, logs an ERROR, and returns an *unfitted* classifier — which falls back to a static VIX/yield-curve rule. Requests still succeed and still report a `macro_regime`, so the degradation is invisible in the response. `scikit-learn`, `hmmlearn`, and `joblib` are pinned exactly for this reason, and bumping any of them requires retraining and recommitting `argus/models/macro_hmm.joblib` in the same change. Check `GET /pipeline/status` → `macro_classifier_fitted` to confirm which mode is live.
- **The System Is Not a Pure Function of Its Inputs**: Reconciled outcomes feed agent reliability back into the aggregator's vote weighting and the portfolio agent's Half-Kelly anchors. The same market inputs therefore produce different allocations as outcome history accumulates. This is intended behaviour, but it complicates reproducibility, regression testing, and any attempt to attribute a change in output to a change in code.
- **A Timed-Out `/analyze` Keeps Spending Quota**: When a graph run exceeds `ARGUS_ANALYZE_DEADLINE_SECONDS` (default 360), the API returns 504 but the underlying worker thread cannot be cancelled and continues to completion, consuming governor budget for a request nobody is waiting on. Asynchronous job submission is noted as future work rather than implemented.
